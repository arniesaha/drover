## Fixed this session

### 1. `codex exec resume` died on every follow-up turn — `093b349`

`codex exec resume` does not accept `--sandbox`; that flag exists only on the
parent `codex exec`. `codex.py:_argv_for` passed it on the resume path, so the
**first turn of every Codex session worked and every turn after it aborted at
arg-parse** with `error: unexpected argument '--sandbox' found`. That is the
error in the reported screenshot, and it is why the session could not act on
"push and merge on main".

Verified against codex-cli 0.144.4: `resume` accepts `-c key=value`,
`--json`, `--skip-git-repo-check`, `--dangerously-bypass-approvals-and-sandbox`
— no `--sandbox`. Now uses `-c sandbox_mode=danger-full-access`, confirmed to
parse (it reaches thread lookup rather than the parser).

The driver test asserted the *broken* argv and passed, because the fake codex
stub accepts any flag. That is the more important lesson here: the stub cannot
detect a CLI contract change. The test now asserts `--sandbox` is absent.

### 2. Structured transcripts were absent from every handoff — `093b349`

**This one breaks the core premise of the project.**

`_build_handoff_prompt` (metrics.py) built its context solely from
`harness_transcript_chunks`. Only the PTY terminal mirror ever writes that
table. Structured (chat-mode) sessions keep their conversation in
`harness_events` and write **zero** chunks.

Live data:

| mode | sessions | with transcript chunks |
|---|---|---|
| pty | 18 | 16 |
| structured | 38 | **0** |

So every structured handoff shipped the literal line:

> Recent transcript: not available in central Drover yet.

Checked all 17 handoff sessions in the DB — 100% of the structured ones were
empty. The continuation agent started with session metadata and no
conversation at all.

New `HarnessRegistry.transcript_text()` prefers recorded chunks and falls back
to replaying the event stream. Replaying real sessions that previously yielded
**0 characters** now recovers 55k / 94k / 559k characters.

Also: `daemon._safe_append_transcript_chunk` is defined and never called — the
only dead function in the file. It looks like the intended structured-chunk
writer that was never wired up.

### 3. Every structured event normalized to `"status"` — `093b349`

`events._infer_type` matches dotted prefixes (`terminal.`, `session.`,
`tool.`, `approval.`). Structured drivers emit **bare underscore names**
(`assistant_output`, `tool_action`, `tool_result`, `user_input`, `error`).
None match, so all of them fell through to the `return "status"` default:
**15,174 of 15,174 structured events in the live DB are `normalized_type =
'status'`.** `tool_result` and `approval_response` were not even in the
vocabulary.

The raw `event_type` column was always correct, which is why the iOS app still
rendered — it parses payloads itself. The **web UI does not**:
`harness_terminal.html:498` styles events by `normalized_type`, so every event
there rendered identically.

### 4. iOS: raw enum reflection shown as an error message — `a146b75`

The `transport("cancelled")` banner in the screenshot is Swift's default enum
reflection. `NexusError` never conformed to `LocalizedError`, and
`SessionStore.errorMessage` fell back to `"\(error)"`.

Worse, the underlying event was benign: a **cancelled request is the app
tearing down its own work** (a superseded poll, a dismissed screen), not the
hub going away — yet it flipped `isReachable` and raised the unreachable
banner over a healthy fleet.

Both fixed. Cancellation is detected from `URLError.code`, not the message:
`localizedDescription` for -999 is a bare `"cancelled"` on some platforms and
`"The operation couldn't be completed. (NSURLErrorDomain error -999.)"` on
others, so no substring test on it is reliable. `NexusClient` normalizes to one
canonical detail string at the boundary.

`MockURLProtocol` gained a `transportError` slot — its handler only models
`(status, body)` pairs, so transport failures were **untestable** and therefore
untested.

### 5. CI had been red since `339ad81` — `4605ed0`

Black failed on two test files the M5 wave left unformatted. The gate only
checks files touched by the diff, so the debt sat invisible until those files
were next modified. Main is green again as of `a146b75`.

## Not fixed — recommended, in priority order

### P1 — Sessions list can't distinguish sessions

`SessionRow` titles rows with the cwd's last path component, so three sessions
in this repo all render as "drover" (visible in the screenshot). `SessionSummary`
carries no branch, no last-message preview, no title — so the fix is not
client-side only. `harness_sessions` already stores `branch`, and
`harness_events.content_preview` has the last message. Suggest adding both to
the `/harness` snapshot payload and rendering branch + a one-line preview.

### P1 — Raw CLI stderr dumped into chat

The screenshot shows the full `error: unexpected argument ... Usage: codex exec
resume ... For more information, try '--help'` block rendered as a chat message.
Driver-level failures should be summarized to one line with the detail behind a
disclosure. Related: `turn exited` appears twice with no explanation, and the
token line (`in 10.4M | out 26.1K | cache 10.1M | reason 5K`) is unlabelled
jargon.

### P2 — Flaky relay E2E test

`test_relay_e2e.py::test_full_session_lifecycle_over_relay` failed in CI on
`4605ed0` ("hub never mirrored a terminal.output event") and passed locally
(1058 passed) and on the next run. Timing-sensitive against slower CI runners.
Worth making deterministic before the repo is public — a flaky suite on a
first-impression repo reads as a broken project.

### P2 — No iOS build or test in CI

`.github/workflows/ci.yml` is Python-only. The iOS app is half the product and
164 Swift tests never run in CI. Add a macOS job running `swift test` in
`apps/drover/NexusKit`.

### P2 — Legacy `nexus` naming leaks into a public repo

128 tracked files still say "nexus": docs reference `~/.nexus/`,
`nexus-collect`, and `docs/install-shipper.md` is full of
`arnabmac@Arnabs-Mac-mini.local`. Test fixtures hardcode
`/Users/arnabmac/jenny/nexus`. The DB stores `handoff_mode = 'nexus_handoff'`.
None of this is a secret leak (scanned — clean), but it is confusing for a
first-time reader and dates the project.

### P3 — `daemon.py` is a 2,750-line monolith

100KB, by far the largest file. HTTP handlers, terminal mirroring, structured
session lifecycle, and worktree management all live together. Worth splitting
along those seams before outside contributors arrive.

### P3 — Housekeeping

- Three merged per-session worktrees under `drover-data/worktrees/` and the
  `.claude/worktrees/usability-m5` worktree (content fully upstream) can be
  pruned. **Not removed — destructive, your call.**
- No linter or type checker; `black` + `isort` only. `ruff` would be cheap.
- `README.md` "Getting started" is three lines and does not cover configuring a
  host, the iOS app, or connecting a second machine.

## Health notes

Genuinely good, and worth saying: 3 TODO/FIXME repo-wide (all in generated
`.build` artifacts), no committed build output, no secrets, a small 13MB
history, Apache-2.0 in place, and 1,058 Python + 164 Swift tests passing. The
comment discipline explaining *why* is unusually strong. The defects above are
concentrated at integration seams — exactly where they hide from unit tests.
