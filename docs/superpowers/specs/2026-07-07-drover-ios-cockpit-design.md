# Drover — iOS Cockpit Design (spec 2 of 3)

Status: approved design, pending implementation plan
Date: 2026-07-07

## Why

Spec 1 (`2026-07-06-headless-harness-protocol-design.md`, deployed) turned
harness sessions into structured message streams: typed JSON turns, first-class
permission prompts, per-session `seq` ordering, `awaiting`/`last_activity`
state, continuous event flow to central, REST history and a per-session
WebSocket. This spec is the native client for that protocol: an iPhone app
that is the fleet cockpit — see every agent across hosts, get pulled in when
one needs you, answer from anywhere.

## Naming

Product name: **Drover** (decision recorded on issue #199 — Threadline failed
availability; Drover checked clean). The app, bundle id `com.arnab.drover`,
and this spec use Drover. The backend repo/package/CLI/services keep `nexus`
until #199's pre-OSS rename stage; this app treats "the Nexus server" as an
implementation detail the user never sees.

## Decisions (made during brainstorm)

- **Free Apple developer account.** Side-load via Xcode (7-day re-sign). No
  APNs, no TestFlight in v1. Notifications are local, driven by iOS
  Background App Refresh (best-effort ~15 min). The notifier is behind a
  protocol so APNs can replace it without UI changes if a paid account
  arrives.
- **Reachability via Tailscale.** User installs Tailscale on the iPhone and
  the Mac Mini; the app's default server URL is central's Tailscale address
  (plain HTTP inside the tailnet — WireGuard encrypts the hop, matching the
  backend's no-TLS/no-Secure-cookie design). LAN URL works identically at
  home.
- **V1 scope: all four surfaces** — session list with attention states, chat
  view with turns/approvals, launch screen, SwiftTerm terminal escape hatch.
- **iPhone first.** Project structure is multiplatform-ready but only the
  iOS target ships in v1; the Mac has the web UI.
- **Architecture approach A**: vanilla SwiftUI + a `NexusKit` Swift package
  for all non-UI logic. No state-management framework. SwiftTerm is the only
  third-party dependency. Xcode project generated by **XcodeGen** from a
  committed `project.yml` (agent-driven development needs reviewable project
  diffs, not pbxproj merges).

The app builds with `xcodegen generate && xcodebuild -scheme Drover …`;
NexusKit tests run headless on the iPhone simulator via `xcodebuild test`.

## Backend surface consumed (all exists today; no server changes required)

- `GET /harness` — hosts + sessions incl. `mode`, `awaiting`, `last_activity`,
  cwd suggestions (bearer).
- `POST /harness/hosts/<id>/sessions` — `{harness, mode:"structured", prompt,
  cwd}` (also `mode:"pty"` for shell).
- `GET /harness/sessions/<id>/messages?after_seq=N` — history + `max_seq`.
- `WS /harness/sessions/<id>/stream` — one JSON text frame per event.
- `POST /harness/sessions/<id>/turns` — `{text}`; 409 = approval pending or
  turn in flight.
- `POST /harness/sessions/<id>/permission` — `{request_id, decision, note?}`;
  400 for harnesses without an approval channel (codex/gemini).
- `POST /harness/sessions/<id>/interrupt`, `POST …/terminate`.
- `WS /harness/sessions/<id>/terminal` — PTY byte stream (SwiftTerm).
- All bearer-authenticated with the shared cluster token.

## Screens

**Sessions (home).** Sections by attention: *Needs you* (awaiting approval or
input), *Working*, *Done/Errored* (collapsed). Each row: harness icon,
repo/cwd short name, host badge, relative last-activity, one-line latest
message preview. Derived state: `errored`/`completed`/`terminated` from
`status`; else `awaiting=="approval"` → needs-you (approval), `awaiting ==
"input"` → needs-you (your turn), else working. Poll `GET /harness` every 5 s
foregrounded; pull-to-refresh. Tapping a structured session opens Chat; a PTY
session opens Terminal.

**Chat.** Messages rendered by type: `assistant_output` as markdown bubbles
(thinking payloads collapsed behind a disclosure); `tool_action`/`tool_result`
as a paired compact card (tool name, input summary, exit/result disclosure);
`user_input` right-aligned; `status` as thin timeline separators (turn
complete, exited); `error` highlighted; `raw` in monospace behind a
disclosure. When the newest message is an unanswered `approval_prompt`, a
pinned banner shows the tool + input with **Approve / Deny** buttons →
`POST …/permission`. Composer sends turns; on 409 it shows "answer the
approval first" or "agent is still working" inline. Toolbar: interrupt,
terminate (confirmation), session info. History loads via REST from seq 0
(paginate later if needed), then the WS stream appends; on WS drop, reconnect
with `after_seq = last seen` (the seq contract makes this gapless and
duplicate-free).

**Launch.** Host picker (from `GET /harness` hosts), harness picker from that
host's capabilities (claude-code / codex / gemini structured; shell as PTY),
cwd field with the server's recent-cwd suggestions, initial-prompt text area.
Creates the session and pushes straight into Chat (or Terminal for shell).

**Terminal.** SwiftTerm view bound to the terminal WebSocket: input, resize
on rotation/keyboard, paste, Ctrl-key bar (Esc/Tab/Ctrl-C/arrows). Offered
for PTY sessions and as an "open terminal" escape hatch on any session's info
sheet. Reuses the existing two-hop authed WS (`Authorization: Bearer` header
on the upgrade).

**Settings.** Server URL (default: Tailscale IP, editable), token (pasted by
the user, stored in Keychain, never rendered back — only "configured ✓"),
connection test button (hits `/healthz` then an authed `/harness`), notification
toggle, app version.

## Data flow and state

`SessionStore` (`@Observable`, main-actor) is the single source of truth the
views render. It owns: the sessions snapshot (from polling), per-open-session
message arrays keyed by `seq`, and connection status. `NexusClient` (actor) is
stateless I/O: typed methods over URLSession + `URLSessionWebSocketTask`,
decoding into `NexusKit` model structs that mirror the wire schema (tolerant
decoding: unknown message types render as `raw`-style fallback rather than
failing — same degradation philosophy as the backend).

Notifications: `BGAppRefreshTask` registered at launch; each grant fetches
`GET /harness`, diffs needs-you session ids against the last-seen set
(persisted in `UserDefaults`), fires one local notification per new needs-you
session ("Claude needs approval in nexus — Bash(git push)…"), and reschedules.
Foreground polling updates the app badge with the needs-you count. `Notifier`
protocol isolates this so an APNs implementation can replace polling later.

## Error handling

- Server unreachable → non-blocking banner + last cached snapshot; retries
  with backoff. First-run unconfigured → routed to Settings.
- 401 anywhere → "token rejected" banner + Settings shortcut (token may have
  been rotated server-side).
- WS drop → exponential backoff (1 s → 30 s cap) reconnect from `after_seq`;
  a "reconnecting" pill shows in Chat during gaps.
- Turn 409 / permission 400 → inline contextual hints, never modal alerts.
- Malformed/unknown message payloads → rendered as raw fallback, never
  dropped, never crash decoding (all model fields optional-tolerant).

## Testing

- **NexusKit unit tests** (the bulk): `NexusClient` against `URLProtocol`
  mocks replaying JSON captured from the live API (session list, message
  batches incl. approval flows, 401/409/400 paths); `SessionStore` state
  transitions (attention derivation, seq-cursor resume, needs-you diffing for
  notifications); Keychain round-trip.
- **Build + smoke**: `xcodegen generate` + `xcodebuild test` on the iPhone
  simulator per task; a final manual pass in the simulator (launch → chat →
  approve → terminal) before device install.
- **Device install** (user's manual step): Xcode → run on phone with free
  signing; re-sign weekly.

## Out of scope (v1)

- macOS target (structure-ready, not shipped), iPad layout polish.
- APNs push, TestFlight (paid account features; Notifier abstraction is the
  seam).
- Cross-harness handoff, project-brief injection, MCP awareness (spec 3).
- Web-UI changes; backend rename (issue #199 staging).
- Multi-server support (one Nexus cluster per install).
- Session search/history browsing beyond the live list (context-plane UI
  lands with spec 3).
