# Public iOS release readiness audit

Audited 2026-10-08 against `origin/main` at `0c9605497bcfbb29070a29d3af85080c8be271dd`. This is a source and documentation audit, with read-only GitHub issue lookup and Apple policy lookup. No deployed hub or host was contacted, and no build or full test suite was run. Issue status is a point-in-time observation. Source references below are pinned to the audited commit. Runtime claims from issues and runbooks are historical evidence, not measurements made for this audit.

Drover is intended to be a free, self-hosted developer tool: strangers operate their own hub and hosts, while OpenClaw/Hermes own orchestration and Drover owns execution, knowledge and continuity. **Not ready for a public TestFlight beta yet.** The viable first release is a private-network, single-operator product. Public distribution of the iOS app does not require public relay ingress. Internet-facing hubs remain unsupported until the separate security gate below is met.

Sizes: S is a focused change, M spans several components, L needs a cross-component design and acceptance journey. Priorities are ranked within each group. P0 gates public TestFlight, P1 gates App Store, P2 follows launch. Proposed fixes and acceptance conditions are recommendations, not completed work.

## Ranked blockers

### P0.1: Authenticate MCP and make profile import fail private

**Evidence:** FastMCP is constructed without an auth provider at [src/drover/server/mcp/server.py:24-81](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/server/mcp/server.py#L24-L81). Its reads include replay, summaries, search, handoffs, fleet status and quota, not just the portable profile [src/drover/server/mcp/server.py:84-444](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/server/mcp/server.py#L84-L444). The general tier filters profile reads only [src/drover/server/profile.py:79-101](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/server/profile.py#L79-L101). MCP also accepts pending profile proposals and `drover_session_close`, which enqueues a summary generation, rather than terminating a process [src/drover/server/mcp/tools.py:807-837](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/server/mcp/tools.py#L807-L837). Import defaults to general, uses heading keywords, cannot select private as the base tier, and auto-accepts first non-private imports [src/drover/server/profile_cli.py:15-72](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/server/profile_cli.py#L15-L72), [src/drover/server/profile_cli.py:143-201](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/server/profile_cli.py#L143-L201). [#558](https://github.com/arniesaha/drover/issues/558) reports sensitive categories falling into general/trusted and missing review keys.

**User impact:** Any process able to reach MCP can read sensitive work history, obtain general profile content, and induce writes or model work. Loopback limits reachability but is not an agent permission boundary. A remote MCP bind expands the exposure. Import can publish sensitive material without a deliberate promotion decision.

**Fix sketch:** Share authenticated credential resolution across HTTP and MCP; authorize individual read/mutation capabilities and profile tiers. Keep remote MCP disabled until protected transport exists. Default all imported items to private with heading-path keys and an explicit promotion preview; scan bodies as an additional warning, never as authority to publish. Verify anonymous replay/search/proposal/enqueue refusal and #558 fixtures. **Size: M. Existing: #558, #545; new MCP security issue proposed.**

### P0.2: Enforce host identity and close credential replay boundaries

**Evidence:** Ordinary non-preflight credentials pass the broad hub gate regardless of host/device scope [src/drover/server/web/auth.py:140-176](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/server/web/auth.py#L140-L176). Relay hello supplies a host ID and the handler attaches it without comparing that ID with the authenticated credential [src/drover/server/web/app.py:1981-2070](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/server/web/app.py#L1981-L2070). Security documentation explicitly admits host impersonation [docs/security.md:73-84](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/security.md#L73-L84). Individual revocation and verifier-only storage already exist [docs/security.md:20-38](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/security.md#L20-L38). Legacy cluster tokens remain enabled by default [src/drover/config.py:654-658](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/config.py#L654-L658). Credential revocation updates the store but does not disconnect relay sockets in that handler [src/drover/server/web/app.py:2524-2536](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/server/web/app.py#L2524-L2536).

**User impact:** Leaking a verifier file is not equivalent to leaking a raw token, but a stolen raw host token remains a replayable bearer. Nothing binds its holder to the original machine. It can claim another host and access broad fleet APIs. Revocation on the next HTTP request does not establish revocation of an already upgraded stream.

**Fix sketch:** Bind enrollment, heartbeat, event producer and relay hello to immutable credential host identity; reject mismatches before upgrade/registration. Separate device, host and operator permissions, with a first-class operator credential so disabling legacy auth does not remove management access. Track credential IDs on active streams and disconnect on revoke/rotate. Add expiry/rotation and document that identity binding alone cannot distinguish a stolen bearer for the same host; use proof-of-possession or short-lived enrolled keys if that threat must be prevented. **Size: M. Existing: [#13](https://github.com/arniesaha/drover/issues/13).**

For the beta, implement host binding and scope enforcement and retain an explicit private-network-only requirement. Before any internet ingress, also require HTTPS/WSS with verified certificates, replay/credential lifecycle review, origin/CSRF review, bounded connections and requests, pairing/login abuse controls behind proxies, firewall isolation of MCP/OTLP/internal/database ports, and an explicit threat review. #13 is necessary but insufficient for public ingress.

### P0.3: Prove a stranger's complete first-run journey

**Evidence:** The installer requires either existing PostgreSQL or an already-running Docker-compatible runtime [docs/getting-started.md:9-42](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/getting-started.md#L9-L42). The iOS instructions still point to a source build [docs/getting-started.md:141-162](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/getting-started.md#L141-L162). Source defaults retain DuckDB compatibility, role `all`, legacy analytics and model assumptions, while fresh central setup selects PostgreSQL [src/drover/config.py:565-637](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/config.py#L565-L637), [docs/postgresql-control-store.md:3-18](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/postgresql-control-store.md#L3-L18). DuckLake provisioning is a separate operator sequence with service environment and platform pins [docs/operations/lake-cutover.md:13-86](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/operations/lake-cutover.md#L13-L86).

**User impact:** Installing the free app does not create a working backend. Database, private routing, CLI login and lake setup can defeat first use. The author-operated distribution smoke proves neither clean installation nor independent ownership.

**Fix sketch:** Publish one supported clean-Mac path with explicit dependency and storage choices, installer-driven readiness and model opt-in. Decide whether beta uses legacy analytics or automatically provisions DuckLake; do not imply the installer's managed control database creates a lake. Replace source-build-only app acquisition with public beta instructions. Record a clean account/device acceptance journey, reboot included, using synthetic content and no author environment. **Size: L. Existing: #481, #414; new onboarding acceptance issue proposed.**

### P0.4: Make stalled ingestion and unsafe updates recoverable

**Evidence:** Lake export commits receipts before PG acknowledgement and retains durable ingress on failures [docs/operations/lake-exporter.md:60-97](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/operations/lake-exporter.md#L60-L97). A lifecycle failure stops export; retry requires a new explicit lifecycle instance [docs/operations/lake-serving.md:84-96](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/operations/lake-serving.md#L84-L96). Outbox diagnostics report outstanding age and published batches older than five minutes [src/drover/server/control_outbox.py:921-949](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/server/control_outbox.py#L921-L949). Liveness can stay 200 and is not a freshness monitor [docs/analytical-recovery.md:31-55](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/analytical-recovery.md#L31-L55). Updates are enabled by default [src/drover/config.py:659-674](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/config.py#L659-L674); harnessd observes a newer hub target, smoke-tests, drains, writes a marker, flips and restarts [src/drover/server/harness/updater.py:361-496](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/server/harness/updater.py#L361-L496). Rollback checks hub registration, not end-to-end execution or data compatibility [src/drover/server/harness/updater.py:511-568](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/server/harness/updater.py#L511-L568). [#465](https://github.com/arniesaha/drover/issues/465) records terminal admission during drain and manual resend rough edges. Cutover preflight explicitly guards pending verification because harnessd can re-flip the shared runtime on startup [docs/operations/lake-cutover.md:77-85](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/operations/lake-cutover.md#L77-L85).

**User impact:** The exporter-stall incident class is a healthy-looking command plane with increasingly stale recall and missing summaries. Durable data can survive while the user cannot recover service. Auto-flip can race terminals or interfere with a hub cutover; successful registration can certify a release whose chat or recall is broken. A code rollback is not a schema rollback.

**Fix sketch:** Gate first-use readiness on synthetic ingest-to-recall progress and expose lag/degraded exporter state in app/doctor with a public recovery procedure. Recreate failed exporter lifecycles through bounded supervised recovery only after fencing is safe. Gate terminal creation during drain, preserve uncertain sends and offer explicit retry/reconciliation. Make beta update policy explicit with pin/disable controls; prove idle activation, hub-outage rollback, no-previous-version handling, shared-runtime restart and migration compatibility in isolated acceptance. **Size: M. Existing: #465, #481, #482, #476.**

## P1 blockers before App Store

### P1.1: Deliver complete backup and restore, not just a control dump

**Evidence:** Managed PostgreSQL already has a dump helper and explicit stopped-server restore [docs/postgresql-control-store.md:53-68](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/postgresql-control-store.md#L53-L68). Lake backup is isolated-copy rehearsal only; full backup must coordinate catalog, referenced files and control store with export watermarks, and production R2 automation remains unavailable [docs/backup.md:3-49](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/backup.md#L3-L49), [docs/backup.md:76-89](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/backup.md#L76-L89). [#98](https://github.com/arniesaha/drover/issues/98) identifies a possible direct terminal detach loss, explicitly unconfirmed.

**User impact:** A preserved container volume is not protection against disk loss or deletion. Restoring only PG loses analytical recall; copying only Parquet loses catalog identity. Terminal mirroring completeness is an unresolved risk, not demonstrated loss. Phone drafts are also not a backup of host execution or hub history.

**Fix sketch:** Provide a provider-neutral local backup first, with one consistent catalog/files/control generation, config and credential recovery instructions, host spool policy, retention and isolated restore verification. R2 should be optional. Give a stranger exact recovery steps and prove recall and session continuity after restore. Instrument direct detach to resolve #98. **Size: L. Existing: #476, #481, #482, #98.**

### P1.2: Bound startup resources and meet cockpit latency at realistic scale

**Evidence:** [#466](https://github.com/arniesaha/drover/issues/466) is open and reports historical multi-GB RSS shortly after restart. Recent macOS documentation distinguishes RSS from physical footprint and reports a much smaller footprint; the budget guard only alerts and does not reject admission or change readiness [docs/operations/hub-memory-budget.md:3-25](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/operations/hub-memory-budget.md#L3-L25). Query-child memory is reported separately [docs/operations/hub-memory-budget.md:69-72](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/operations/hub-memory-budget.md#L69-L72). [#542](https://github.com/arniesaha/drover/issues/542) records about two seconds for cockpit overview and receipt-count growth; batching reduced measured proof work, but its release/re-measure gate remains open. The cutover runbook's cockpit gate is p95 below two seconds [docs/operations/lake-cutover.md:119-135](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/operations/lake-cutover.md#L119-L135), looser than #542's 1.2-second target.

**User impact:** A small Mac can swap, hang or experience startup spikes; stale benchmarks can pass while ordinary cockpit reads regress as receipts accumulate. RSS alone can also incorrectly diagnose macOS live memory consumption.

**Fix sketch:** Reconcile the latency thresholds and measure synthetic fresh/aged lakes, startup peak footprint, Linux RSS and aggregate query-child resources. Set supported hardware requirements from results. Bound resident caches/startup work, isolate analytics as needed and refuse heavy admission under resource pressure while preserving control. Verify the batching fix is present in the candidate and no longer grows per receipt. **Size: M. Existing: #466, #542, #481.**

REST maps 404 to unavailable and schema failures to decoding errors [apps/drover/DroverKit/Sources/DroverKit/DroverClient.swift:833-881](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/apps/drover/DroverKit/Sources/DroverKit/DroverClient.swift#L833-L881). Message streams have reconnect, cooldown and explicit unauthorized handling [apps/drover/DroverKit/Sources/DroverKit/MessageStream.swift:84-126](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/apps/drover/DroverKit/Sources/DroverKit/MessageStream.swift#L84-L126), [apps/drover/DroverKit/Sources/DroverKit/MessageStream.swift:236-280](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/apps/drover/DroverKit/Sources/DroverKit/MessageStream.swift#L236-L280). **User impact:** There is feature negotiation, but these paths do not establish a fleet-wide minimum/maximum contract. An older hub hides cockpit, a future incompatible version can be treated as supported, and malformed fleet data can appear as an empty fleet. Missing routes and incompatible responses show ordinary availability/decoding errors. App Store updates and autonomous host updates can skew independently. **Fix sketch:** Publish supported version ranges; negotiate protocol/features before mutation and show an actionable upgrade/pin message. Exercise old/current/new hub and host combinations, bad payloads, reboot, protected storage unavailable, app kill during a send, lost acknowledgement, offline sign-out and network switching on a physical phone. Confirm no duplicate send or silent draft loss. This audit does not establish that the app crashes; crash-free acceptance remains unproven. **Size: M. Existing: #414, #465; new compatibility acceptance issue proposed.**

### P1.4: Complete Apple review and accurate privacy disclosures

**Evidence:** Distribution verifies signing and an embedded manifest [apps/drover/docs/distribution.md:168-183](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/apps/drover/docs/distribution.md#L168-L183), but the documented TestFlight export is internal-only [apps/drover/docs/distribution.md:185-222](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/apps/drover/docs/distribution.md#L185-L222). The lane enables arbitrary network loads and accepts independent HTTP/HTTPS hubs [apps/drover/docs/distribution.md:192-198](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/apps/drover/docs/distribution.md#L192-L198). The manifest declares linked name, device ID, user content, photos/video and other data, no tracking, and a UserDefaults required-reason entry [apps/drover/Drover/PrivacyInfo.xcprivacy:1-82](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/apps/drover/Drover/PrivacyInfo.xcprivacy#L1-L82). The privacy page contains an outdated statement that sign-out leaves registration, followed by newer self-revocation behaviour [docs/privacy.md:62-65](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/privacy.md#L62-L65), [docs/privacy.md:87-95](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/privacy.md#L87-L95).

**User impact:** Signing success does not imply external TestFlight or App Store review readiness. Reviewers need a functioning journey without the author's private fleet or personal model account. Users need a clear distinction between a free app and optional paid agent/provider services. Privacy text currently contradicts itself and does not fully cover portable profiles.

**Fix sketch:** Prepare review notes and a synthetic review environment or approved full demo path. Explain that terminal/agent execution occurs on the user's enrolled computer and that iOS is the native remote client; show permissions and host-side control. Address executable-code and remote-client classification as review risks, not an asserted ban. Check provider login/account-management flows against the applicable classification. Document external beta distribution separately. Review the signed privacy report and dependency APIs, reconcile App Store Connect answers with actual operator/provider flows, remove stale sign-out text and add profile, deletion, transport and lock-screen disclosures. **Size: M. Related: [#390](https://github.com/arniesaha/drover/pull/390) (merged distribution PR); new Apple review/privacy issue proposed.**

Their application here is an inference requiring review, not a guaranteed rejection or approval. Apple asks for full review access and an accessible backend. [App privacy details](https://developer.apple.com/app-store/app-privacy-details/) and [privacy manifest documentation](https://developer.apple.com/documentation/bundleresources/describing-data-use-in-privacy-manifests) require evaluating actual collection and SDK behaviour; self-hosting alone does not settle the publisher's App Store Connect answers. Sources checked 2026-10-08.

### P1.5: Publish a harness-neutral orchestration contract

**Evidence:** Drover already offers execution HTTP and read MCP, and an authenticated continuity observer endpoint with leases, report, consume and acknowledgement [docs/openclaw-owner-protocol.md:19-93](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/openclaw-owner-protocol.md#L19-L93). Its inactive OpenClaw plugin has synthetic authenticated tests, but live discovery/parent messaging and Hermes remain unverified [docs/openclaw-owner-protocol.md:10-17](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/openclaw-owner-protocol.md#L10-L17), [docs/openclaw-owner-protocol.md:124-134](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/openclaw-owner-protocol.md#L124-L134). Core continuity maps CI outcomes to corrective/review actions and owns retry budgets [src/drover/server/harness/continuity.py:26-35](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/server/harness/continuity.py#L26-L35), [src/drover/server/harness/continuity.py:286-360](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/server/harness/continuity.py#L286-L360). MCP quota includes a routing hint [docs/mcp.md:71-85](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/mcp.md#L71-L85).

**User impact:** Orchestrators can consume facts and execute sessions, but adoption still depends on a factory-specific protocol and runtime integration. Policy vocabulary in the continuity store can couple Drover to one orchestration workflow.

**Fix sketch:** Keep durable events, leases/fencing, checkpoints, replay and execution in Drover. Move task decomposition, provider selection, CI next-action policy and retry decisions to OpenClaw/Hermes, retaining delivery mechanics in Drover. Document the existing HTTP execution surface as an external API with idempotency/outcome reconciliation, scoped service credentials and versioning. Generalize factory-specific continuation to owner-neutral events and add a supported subscription/cursor contract for orchestrator recovery. Prove one OpenClaw and one Hermes synthetic journey. Do not claim execution APIs are absent: the missing product is a stable neutral integration contract and verified adapters. **Size: L. Existing: #497, #487, #501.**

## P2 follow-ups after launch

### P2.1: Internet ingress as a separate supported deployment

**Evidence:** Public relay exposure remains explicitly unsupported [docs/multi-host.md:103-128](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/multi-host.md#L103-L128), [docs/security.md:113-125](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/security.md#L113-L125). **Impact:** Remote users must arrange private networking. **Fix sketch:** Complete the P0.2 internet threat gate, publish a tested TLS ingress recipe and abuse/resource limits, and run isolated adversarial acceptance before changing the support statement. Do not open MCP or OTLP alongside the app port. **Size: L. Existing: #13.**

### P2.2: Automate retention and optional offsite recovery

**Evidence:** No unified retention covers all context and backups [docs/privacy.md:79-85](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/privacy.md#L79-L85); lake retention and production offsite workflow need implementation [docs/backup.md:76-89](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/backup.md#L76-L89). **Impact:** Disk growth and personal-content accumulation continue after sessions end. **Fix sketch:** Add user-configurable retention, disk-pressure reporting, profile/history deletion and optional encrypted offsite generations with restore drills. Deletion must respect catalog references and backups. **Size: M. Existing: #476, #547.**

## Network surface inventory

All built-in hub/harness listeners use plaintext transport; the hub does not terminate TLS [docs/privacy.md:44-49](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/privacy.md#L44-L49). Private Tailscale can protect traffic between peers, while ordinary LAN HTTP sends bearer credentials and content without transport encryption. A reverse proxy can terminate TLS but must not broaden supported ingress by implication.

| Surface | Auth and transport | Anonymous reach and actions | Evidence |
| --- | --- | --- | --- |
| Hub API, cockpit HTML/JSON, metrics, session history, host provider auth, execution mutations | Bearer legacy token or active credential; HMAC session cookie also passes the common gate. ## Clean-Mac onboarding checklist and hidden assumptions

This is the complete documented dependency chain, not a claim that it has been executed here.

1. Obtain Python 3.11+ and a supported agent CLI, authenticate that CLI and choose a readable checkout. The installer supplies uv but not the agent's account or a container runtime [docs/getting-started.md:48-55](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/getting-started.md#L48-L55). The app is free; model accounts and infrastructure may cost money.
2. Choose an existing dedicated PostgreSQL database/role and securely provide its DSN, or install/start Docker-compatible software before choosing managed mode. Managed mode provides a pinned PG 17 container, private service env, loopback publication and persistent volume; the operator still owns runtime startup, capacity and recovery [docs/postgresql-control-store.md:13-39](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/postgresql-control-store.md#L13-L39), [docs/postgresql-control-store.md:53-68](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/postgresql-control-store.md#L53-L68). Fresh central PostgreSQL is required by the supported installer, profile and durable memory path; old/local DuckDB compatibility does not provide an equivalent central product.
3. Run the central installer with the chosen store mode. It verifies a release, installs a versioned runtime, initializes control state, creates and loads services and prints pairing. Existing source services require explicit adoption [docs/getting-started.md:18-37](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/getting-started.md#L18-L37). The source alternative requires sync, config initialization, control initialization and an environment DSN on every start [docs/getting-started.md:62-114](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/getting-started.md#L62-L114).
4. Choose the analytical path explicitly. Fresh installation is not the author's DuckLake deployment. For DuckLake, create a separate catalog and logins, verified extension/engine pins, data root, seed/rebuild, exporter provisioning, role grants, verify and any import. Persist reader/exporter env in the service, run preflight/gate, then backup/switch/verify/soak [docs/operations/lake-cutover.md:9-86](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/operations/lake-cutover.md#L9-L86). Preflight assumes a particular macOS server LaunchAgent label, substantial free disk/RAM and a bounded history size. This is an operator runbook, not an automatic first-run wizard.
5. Confirm hub and local harness readiness and host registration. Generated services capture a PATH and derive host ID from the local machine name [install.sh:631-691](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/install.sh#L631-L691). After reboot, Docker and the agent user's authenticated environment must still work. Agent binaries installed outside the captured PATH, mounts unavailable at service start, duplicate short machine names and user-session service startup are assumptions to check.
6. Arrange a private LAN or install/sign into private Tailscale on Mac and phone. Set bind and advertised URL consistently; source pairing otherwise advertises loopback. Firewall the intended ports. Address detection can prefer an overlay address that disappears when VPN stops, leaving the hub alive but unreachable [docs/getting-started.md:154-158](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/getting-started.md#L154-L158), [docs/getting-started.md:175-234](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/getting-started.md#L175-L234). No publisher cloud account is required.
7. Pair additional hosts with `pair-host` and paste the emitted installer command before its 15-minute expiry. Probe chooses direct or relay; relay remains private. Manually restrict direct daemon ingress [docs/multi-host.md:45-128](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/multi-host.md#L45-L128). Confirm each host's ID, route and heartbeat. Revoke a lost host/device independently.
8. Acquire the app through the beta/store path when available; current public guide still requires source build. Pair by QR or manual URL/code within ten minutes, permit camera/local network as needed, and select a host, authenticated harness and valid project [docs/getting-started.md:141-173](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/getting-started.md#L141-L173). Notifications are optional. User-owned hubs need their own Apple APNs provider configuration to send push; blank config makes it inert [src/drover/config.py:678-682](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/config.py#L678-L682). The app's distribution certificate does not provision users' hubs.
9. Send a small task and verify response, terminal where enabled, ingest, summary and recall. Run setup-check/doctor for failures. Configure model workers deliberately: defaults name Claude CLI summarization and specific optional local/embedding models [src/drover/config.py:614-637](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/config.py#L614-L637). CLI login on a host does not necessarily configure a hub-side worker account. Install/pull optional local models, set provider keys or endpoints, and explain disabled/failed derived features.
10. Establish a backup and rehearse restore; pin updates during setup/cutover. Turn off legacy cluster auth only after proving device and host upstream paths and retaining operator management. Configure favourite directories per host rather than copying the author's mounts [docs/multi-host.md:130-152](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/multi-host.md#L130-L152).

Author-specific infrastructure should be described as configurable requirements, never copied: personal checkouts/mounts, fleet names/addresses, model subscriptions, local model LaunchAgents and deployment scripts. Defaults for favourite paths and model endpoints are empty [src/drover/config.py:614-637](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/config.py#L614-L637), [src/drover/config.py:675-677](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/src/drover/config.py#L675-L677). The fixed service-label and macOS cutover assumptions above remain. Public guidance also conflicts: Getting Started says Drover does not manage PG's server process while documenting a managed-container mode [docs/getting-started.md:18-42](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/docs/getting-started.md#L18-L42), and its source-build Xcode minimum differs from the distribution toolchain [apps/drover/docs/distribution.md:146-153](https://github.com/arniesaha/drover/blob/0c9605497bcfbb29070a29d3af85080c8be271dd/apps/drover/docs/distribution.md#L146-L153).

Failures without a clear first-run product error include lenient decoding showing empty fleet, absent cockpit capability hiding features, export failure requiring restart despite working execution, unavailable models leaving summaries empty, and an unavailable advertised network leaving the app timing out. Existing setup-check, auth errors, code expiry, bind retry logs and update status are useful safeguards; promote them into one visible readiness journey rather than asking strangers to infer progress from logs.

## Proposed five-iteration sequence

1. **Security baseline:** P0.1 and P0.2, including tokenless daemon fail-closed policy, upstream credential routing and stream revocation. Exit: isolated anonymous and cross-host attempts rejected; private/general import requires explicit promotion. Keep internet ingress unsupported.
2. **Independent first run:** P0.3 plus P0.4 readiness and recovery. Choose the shipped analytics path, automate or document its full setup, pin beta updates and prove clean Mac to independent phone to recall after reboot. Exit: a tester needs no author scripts, paths or accounts.
3. **Durability and updates:** finish P0.4 acceptance and P1.1. Exit: stalled exporter recovers without loss/duplication, updates cannot cut a new terminal/turn, full local backup restores into isolated stores and recall matches receipts.
4. **Scale and interoperability:** P1.2, P1.3 and P1.5. Exit: aged-lake latency and aggregate resource gates pass; supported skew/offline journeys pass; both orchestrator adapters reconcile lost replies using scoped credentials.
5. **Review candidate:** P1.4, physical crash/offline evidence and public beta feedback. Exit: external TestFlight distribution works, review can access synthetic functionality, manifest/privacy/store answers agree, app is clearly free with operator/provider prerequisites. Submit to App Store only after P1 gates pass; schedule P2 separately.
